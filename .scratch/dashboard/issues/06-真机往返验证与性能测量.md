## 验证记录（2026-10-28）

脚本 `tools/measure_t06.py`，走的是服务自己的 HTTP 接口（和页面点按钮同一条路），
不是直接调 pyvmomi，所以测的是端到端耗时。原始数据在 `.scratch/t06.json`。

目标机：`165-东安实业测试`，moref 35，CentOS 7，8 核 / 16 GB，宿主 192.168.2.152。

| 步骤 | 实测 | 结果 |
|---|---|---|
| 起始状态 | — | `poweredOn` / `guestToolsRunning` |
| 优雅关机 | **94.0s**（任务墙钟 94.0s，HTTP 202） | 完成，状态确认 `poweredOff` / `guestToolsNotRunning` |
| 开机 | **1.5s** | 完成，`poweredOn` |
| 等 Tools 就绪 | **11.9s**（自开机算起） | `guestToolsRunning` |
| 冷采集 1 | 1.521s | 3 台主机 / 79 台虚拟机 |
| 冷采集 2 | 1.023s | 同上 |
| 冷采集 3 | 0.576s | 同上 |
| 缓存命中 | 0.002s | 10 秒缓存内 |
| 结束状态 | — | `poweredOn` / `guestToolsRunning`，与开始时一致 |

结论：三台全量刷新 0.58～1.52 秒，明显优于 5 秒要求；往返后虚拟机恢复原状态。

注：本项测量时该虚拟机刚开机、`guest.ipAddress` 还是 `null`，属正常（Tools 就绪后才会报 IP）。
优雅关机的 94 秒是客户机自己关机的时间，不是接口开销。

## 实现取舍

- 测的是 HTTP 接口而不是库函数：页面能点到的路径才是用户能感知的路径。
- 每次采集前要等 10 秒缓存过期，否则第二轮直接命中缓存、测不出冷耗。
