## 踩坑记录（都是真卡住过的）

### 坑 1：CentOS 7 的 python3 是 3.6，程序起不来

```
from __future__ import annotations
SyntaxError: future feature annotations is not defined
```

`from __future__ import annotations` 要 Python 3.7+。三条路都试过：

- **系统 `yum install python3`** → 只有 3.6.8，直接出上面那个语法错误。
- **SCL（rh-python38）** → `centos-release-scl` 能装，但 `centos-sclo-rh` 的
  `mirrorlist=http://mirrorlist.centos.org?...` 随 CentOS 7 EOL 已失效，报
  `Cannot find a valid baseurl for repo: centos-sclo-rh/x86_64`。改成阿里云 vault
  （`https://mirrors.aliyun.com/centos-vault/7.9.2009/sclo/$basearch/rh/`，curl 200；
  `vault.centos.org` 同路径返 403）后能解析，但 yum 变得极易卡死几分钟，放弃。
- **Miniconda 最新版** → `Installer requires GLIBC >=2.28, but system has 2.17`。
  **必须用 `Miniconda3-py38_4.12.0`**（73MB，Python 3.8.13）才在 glibc 2.17 上装得下。

> yum 被中断后远端进程还活着，会占住 `/var/run/yum.pid`，后续命令全卡在
> `Another app is currently holding the yum lock`。清理：`pkill -9 -f yum; rm -f /var/run/yum.pid`。

### 坑 2：pyvmomi 新版在 3.8 上 import 就崩

```
Exception: Python 3.10 or newer is required (found 3.8)
```

pyvmomi 9.x 在 `_init_utils.py` 里做了运行时版本检查。所以 `requirements.txt` 用环境标记：

```
pyvmomi>=8.0.0,<9 ; python_version < "3.10"
pyvmomi>=8.0.0   ; python_version >= "3.10"
```

实际装到 `pyvmomi 8.0.1.0` + `cryptography 47.0.0`，可用。

### 坑 3（最要命）：`_fernet()` 自死锁，接第一台主机就整进程挂死

现象：登录一次成功，之后所有请求（包括再次登录）全部无响应，
`curl` 只能等到超时；journal 里没有任何异常，线程数一直涨。

`py-spy dump --pid <pid>` 一次定位 —— 所有线程都停在同一行：

```
Thread-6  machine_key (store.py:126) ← _fernet (145) ← encrypt_secret ← add_host
Thread-9  machine_key (store.py:126) ← _sign ← _make_session ← _login
```

根因：`_fernet()` 在持有 `_key_lock` 的情况下调用 `machine_key()`，
而 `machine_key()` 自己也要 `with _key_lock` —— `threading.Lock` 不可重入，自己等自己。

```python
# 错误
with _key_lock:
    _fernet_cache["obj"] = Fernet(machine_key())

# 正确（machine_key 自己会加锁）
_fernet_cache["obj"] = Fernet(machine_key())
```

**Windows 上测不出来**：那边密码走 DPAPI，根本不经过 Fernet。
回归用例 `tools/smoke_secrets.py`（Linux 上 8/8 通过，Windows 上自动 SKIP），
用 watchdog 线程确保"卡住"能被判失败。

### 坑 4：systemd 重启后端口从 8787 顺延到 8788

`allow_reuse_address = False` 在 Windows 上是对的（那边 SO_REUSEADDR 是"允许抢占"，
两个进程能同时绑同一端口）；但在 Linux 上它连 TIME_WAIT 都不许跨过，服务重启时
前一秒的 TIME_WAIT 会把 8787 顶掉，服务悄悄落到 8788 —— 端口就不确定了。

改成按平台区分：

```python
allow_reuse_address = sys.platform != "win32"
```

POSIX 上 SO_REUSEADDR 抢不走正在监听的端口，只是允许跨过 TIME_WAIT，是正确语义。

### 坑 5：401 时不读请求体，会毒化 keep-alive 连接

未登录时 `_route` 直接回 401 而没读 body，残留字节被下一个请求当成请求行：

```
code 400, message Bad request syntax ('{"name":"ESXi-152",...,"password":"***"}')
```

修法：401 分支先 `self.close_connection = True` 再回响应，让客户端重建连接。

### 坑 6：PyPI / conda 源的选择

- `repo.anaconda.com` 在这台机上直连下载会失败；`mirrors.aliyun.com/anaconda/miniconda/...` 是 404；
  **清华镜像 `mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/` 可用**（约 700 KB/s）。
- 大文件下载别让 curl 打进度条，用 `curl -fsSL -o`，否则日志会淹掉终端输出。
