# vm_bord 需求总结

## 1. 背景

内网三台 VMware ESXi 单机，日常巡检和临时开关机要分别登录三个 Host Client 页面，来回切。

| 主机 | 版本 | 规格 | 虚拟机 |
|---|---|---|---|
| 192.168.2.152 | ESXi 6.7.0 U2 (build 13644319) | 8 核 / 31.8 GB | 17 |
| 192.168.2.153 | ESXi 6.7.0 U2 (build 13644319) | 8 核 / 31.8 GB | 22 |
| 192.168.2.154 | ESXi 6.7.0 U3 (build 15160138) | 8 核 / 127.8 GB | 40 |

合计 **79 台虚拟机**：开机 15、关机 64、挂起 0。三台的 22 端口（SSH）都是关的，只有 443 上的 vSphere Web Services API 可用 —— **所以只能走 SOAP API，不能登机器跑命令**。这一点决定了整个技术路线。

## 2. 目标

一个跑在本机的网页看板：

- 一页看到三台主机的资源概况和全部 79 台虚拟机；
- 能就地开关机；
- 能增删 ESXi 主机；
- 双击桌面快捷方式就能打开；也能从 DSH Desktop 侧栏一键拉起。

## 3. 角色与场景

单用户（本机操作者）。没有登录、没有权限分级、不做多用户 —— 只监听 `127.0.0.1`（Q5）。

典型场景：

1. **巡检**：早上打开看板，一眼看清哪几台在跑。
2. **临时用机**：找到目标虚拟机 → 开机 → 等 Tools 就绪。
3. **收尾**：把忘了关的测试机关掉。
4. **扩容**：新来一台 ESXi，填地址和账号加进来。

## 4. 范围

### 4.1 做

- 主机接入与移除（增删的是 **ESXi 主机**，不是虚拟机 —— Q3）
- 主机级资源卡
- 聚合虚拟机表 + 搜索 + 排序 + 主机筛选 + 手动刷新
- 单台虚拟机：开机 / 优雅关机 / 优雅重启；强制断电 / 重置作为二级确认操作
- 本地审计记录
- 启动入口：`start.bat` + Windows 桌面快捷方式 + DSH Desktop 侧栏启动器（第二期）

### 4.2 不做（明确排除）

| 不做 | 原因 |
|---|---|
| 在 ESXi 上新建 / 删除虚拟机 | ESXi 单机不支持清单文件夹（`CreateFolder` 抛 `vmodl.fault.NotSupported`），超出一期范围 |
| 批量操作（全主机开机 / 多选关机） | 79 台误操作代价太大，一期只做单台（Q18） |
| 历史曲线、趋势图、告警 | 一期只做当前快照（Q1） |
| 内嵌控制台 / 屏幕画面 | ESXi 6.7 已移除浏览器内嵌控制台，只能 VMRC；只做外链跳 Host Client（Q7） |
| 用户名密码登录看板 | 本地单用户（Q5） |
| 开机自启、系统托盘 | 一期不做（Q12） |
| 自动定时刷新 | 只做手动刷新（Q6） |
| 修改 DSH 本身 / 改 app.asar | 明确不做 |

## 5. 功能需求

### FR-01 主机接入

添加一台 ESXi 主机：名称（备注）、地址、端口（默认 443）、账号、密码。

**保存前必须做连通性校验**：登录 + 读取主机摘要。校验失败**不保存**，并给出可读原因（连接被拒绝 / 证书错误 / 账号或密码错误 / 超时）。

**验收**：填错密码点保存 → 弹出"账号或密码错误"，列表里不出现该主机；填对 → 出现在主机卡里。

### FR-02 主机移除

删除主机前二次确认，要求输入该主机地址确认。移除后不再采集该主机，已接入的其他主机不受影响。

**验收**：删除 .153 → 只要求确认 .153，删除后 .152 和 .154 的虚拟机仍在表里。

### FR-03 主机资源卡

页面顶部按主机数渲染卡片，每张包含：

- 主机名、版本与 build、连接状态（在线 / 离线 + 原因）
- CPU 型号、核数、**当前使用率（%）**
- 内存 总量 / 已用 / 使用率
- 数据存储各卷：名称、总量、剩余
- 虚拟机数 / 开机数
- "打开 Host Client"外链（跳 `https://<ip>/ui`）

主机级指标来自 vSphere HostSystem，**不下钻到虚拟机内部**（Q1）。

**验收**：三台都显示；把 .153 拔网后点刷新，.153 卡片显示离线及原因，另外两张正常。

### FR-04 聚合虚拟机表

一张表装下所有主机的虚拟机，列为：

名称、主机、IP、操作系统、电源状态、内存、磁盘、Tools 状态、操作。

带主机下拉筛选（Q4：单页聚合，不分 tab）。

### FR-05 搜索

按名称或 IP 即时过滤（前端过滤，输入即生效）。

**验收**：输入 `东安` 只剩匹配行；清空恢复全量。

### FR-06 排序

点表头按 **名称 / 电源状态 / 内存 / 磁盘** 排序，再点切换升降序。默认按名称升序。

### FR-07 刷新

手动刷新按钮。刷新中按钮置灰并显示进度；完成后显示"最后更新于 HH:mm:ss"。

10 秒内的重复点击直接走缓存，不重复登录三台主机（Q6）。

采集用并发，三台各自超时 10 秒，单台失败不影响其他台。

### FR-08 电源操作

每行三个按钮：**开机、关机、重启**。

- **关机** = 优雅关机（Guest Shutdown），需要 VMware Tools 正在运行。Tools 不可用或虚拟机已关机时按钮置灰，并提示"只能强制断电"。
- **重启** = 优雅重启（Guest Reboot），同上规则。
- **强制断电 / 重置** 收在二级菜单里，红色，要求勾选确认并**输入虚拟机名称**才可执行（Q2）。
- 操作后按钮进入"进行中"状态，轮询任务结果；成功后刷新该行，失败则原样显示 vSphere 的错误信息，不吞异常。
- 所有操作写审计记录。

**验收**：对一台 Tools 正常的开机虚拟机点优雅关机 → 按钮变"关机中" → 变"已关机"；关掉 Tools 后按钮置灰。

### FR-09 操作系统字段

运行中且 Tools 正常时用虚拟机内部上报的系统名；否则回退到虚拟机配置里的客户机系统类型。

**为什么需要回退**：79 台里 64 台是关机的，关机虚拟机一定拿不到 Tools 上报值（Q17）。

**验收**：64 台关机虚拟机该列不出现空白，显示形如 `CentOS 7 (64-bit)`。

### FR-10 内存与磁盘列的口径

- **内存**：显示配置内存（如 `16 GB`）；运行中且 Tools 正常时，括号附实时占用（如 `16 GB (用 3.2 GB)`）。
- **磁盘**：该虚拟机各虚拟磁盘容量之和（配置值）。

原因同上：关机虚拟机没有实时值（Q17）。

### FR-11 行内展开详情

点击一行展开只读详情：CPU 核数、内存、磁盘、VMX 路径、UUID、开机时间、IP。

不做独立详情页、不做抽屉（Q1 已把资源下钻排除在范围外）。

### FR-12 审计记录

每次电源操作、主机增删都追加一条记录：时间、对象、动作、结果、错误信息。只追加不改写，落本地 JSONL 文件。一期不提供审计查询界面。

### FR-13 DSH Desktop 启动器（第二期）

侧栏一个入口，点开是一个极简面板：

- 本地服务状态灯（运行中 / 未运行）+ 端口
- "启动"按钮 → 探测端口 → 未运行则拉起 Python → 等到健康 → 打开默认浏览器
- "停止"按钮 → 调本地服务的 `/api/shutdown`
- "在浏览器打开"按钮

**该面板不含任何看板功能**，只负责拉起和跳转。本地服务独立存活，DSH 关闭不会杀掉它（Q16）。

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 监听地址 | 仅 `127.0.0.1:8787`，不监听 0.0.0.0（Q5、Q12） |
| 凭据存储 | 密码用 Windows DPAPI 加密后存本地配置文件，机器与用户绑定；页面永不回显密码，编辑时留空表示不修改（Q11） |
| 证书 | ESXi 是自签证书，跳过链校验；首次连接记录证书 SHA256 指纹，指纹变化时在主机卡上提示 |
| 依赖 | Python 3.12 + `pyvmomi`，其余全用标准库；前端零构建 |
| 响应 | 79 台正常网络下，一次完整刷新 ≤ 5 秒 |
| 并发 | 三台主机并发采集 |
| 异常 | 任何一台主机不可用不能拖垮整页；错误必须原样显示，不静默 |

## 7. 数据与状态

- `data/hosts.json`：已接入的主机清单 + DPAPI 密文密码 + 证书指纹 + 备注。
- `data/audit.jsonl`：审计记录，只追加。
- 两者都**不进版本库**（`.gitignore`）。

## 8. 界面结构

单页，自上而下三个区块（Q4）：

1. 顶部：主机资源卡（按主机数量自适应一行）
2. 中间：虚拟机表（搜索框 + 主机筛选 + 刷新按钮 + "最后更新于"）
3. 右上角：设置抽屉（主机管理：增删改、测试连通性）

配色跟随系统深浅色。

## 9. 关键技术决策

见 [ADR 0001](adr/0001-独立本地页面与DSH启动器壳.md)（为什么不用 DSH 内嵌面板）与 [ADR 0002](adr/0002-python-pyvmomi.md)（为什么用 Python）。

两条都源自同一个现实：**插件面板禁止 iframe，且第三方插件每次改动都要手动重启 Desktop**，不适合一个还在反复调的看板。
